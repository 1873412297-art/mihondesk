# 书架同步冒烟测试指南

> 目的：在真机/桌面真实环境中验证手机端 ↔ 桌面端书架同步的 P0 行为（收藏、已读、分类、阅读进度）。
> 构建时间：2026-09-25，对应提交 `26ca5c8f3`（feat(app): integrate library sync on Android）。

## 1. 产物位置

| 端 | 产物 | 路径 |
| --- | --- | --- |
| Android | debug APK（arm64） | `app/build/outputs/apk/debug/app-arm64-v8a-debug.apk` |
| Android | 通用包（模拟器/其他 ABI） | `app/build/outputs/apk/debug/app-universal-debug.apk` |
| Windows | 便携 app image（免安装，含运行时） | `desktop-app/build/compose/binaries/main/app/mihondesk/mihondesk.exe` |

> 注意：`mihondesk.exe` 是开发构建的 app image，不是经过发版门禁（`verifyCleanDistribution`）的正式发行包，仅用于功能冒烟。正式 EXE/MSI 走 `scripts/` 下的发版流程。

## 2. 环境准备

1. **同步目录**：在本机建一个空目录作为两端共享的"同步目录"，例如 `D:\mihon-sync\`。真实使用时这是云盘/WebDAV 挂载目录；冒烟用本地目录即可（验证协议与合并逻辑，不验证云盘同步本身）。
2. **安装手机端**：`adb install -r app/build/outputs/apk/debug/app-arm64-v8a-debug.apk`（或拷贝到手机直接安装；debug 包允许覆盖安装，签名一致时保留数据）。
3. **启动桌面端**：双击 `desktop-app/build/compose/binaries/main/app/mihondesk/mihondesk.exe`。
4. **前置条件**：两端各自能正常浏览/添加漫画（网络可用、至少一个图源扩展可用）；手机与电脑时间已同步（水位用 Unix 毫秒，但跨设备比较依赖时间大致一致）。

## 3. 用例

### 用例 1：收藏同步（手机 → 电脑）

1. 手机端：设置 → 数据与存储 → **书架同步**，打开开关，选择同步目录（SAF 目录选择器选 `D:\mihon-sync` 对应位置；本地目录冒烟时也可选任意可写 SAF 目录）。
2. 手机端：书架中收藏一本漫画 A（或从浏览页添加一本）。
3. 手机端：点"立即同步"。
4. 桌面端：设置 → Backup & Restore → **书架同步**，打开开关，目录选 `D:\mihon-sync`，点"立即同步"。
5. **预期**：桌面端书架出现漫画 A，分类/封面正确。桌面端同步结果显示成功（可在 import_report / 设置页查看）。

### 用例 2：已读进度同步（电脑 → 手机）

1. 桌面端：打开漫画 A 的某一章，翻几页后退出（产生 `last_page_read` 与 history）。
2. 桌面端：立即同步。
3. 手机端：立即同步。
4. **预期**：手机端该漫画对应章节显示已读/进度一致；继续阅读时从相同页码开始。

### 用例 3：分类同步（双向）

1. 手机端：新建分类"正在追"，把漫画 A 移入；立即同步。
2. 桌面端：立即同步。
3. **预期**：桌面端出现"正在追"分类且漫画 A 在其中（ manga_category 关联同步）。
4. 反向：桌面端把漫画 A 移出该分类 → 同步 → 手机端刷新后一致。

### 用例 4：取消收藏（验证 favorite LWW）

1. 手机端：取消收藏漫画 A；立即同步。
2. 桌面端：立即同步。
3. **预期**：桌面端漫画 A 从书架消失（favorite=false 被 LWW 正确传播，而不是被 OR 复活）。
4. 反向再验证一次（电脑取消 → 手机消失）。

### 用例 5：增量与幂等（验证水位/游标模型）

1. 两端完成用例 1–4 后，**不做任何修改**，各自再点 2 次"立即同步"。
2. **预期**：同步目录中不再产生新的 `<deviceId>.<cursor>.pb` 文件（空变更跳过推送）；设置页结果显示"无变更"或条目数为 0。
3. 阅读时长检查：手机端某章累计阅读一段时间后，连续同步 3 次，**预期**该章阅读时长不翻倍（`upsertSyncHistory` 的 MAX 幂等语义）。

### 用例 6：冲突收敛（双端同时改）

1. 两端同时处于"已同步"状态。手机端把漫画 A 加入分类 X，桌面端（同步前）把漫画 A 改名或改备注。
2. 两端先后立即同步，再各自同步一次。
3. **预期**：两端最终状态一致（分类归属与元数据都收敛）；无无限振荡（再同步一轮结果不变）。

## 4. 通过标准

- 用例 1–4 全部符合预期（P0 数据面正确）。
- 用例 5：同步目录无冗余 changeset 文件堆积、阅读时长不膨胀。
- 用例 6：双端收敛且无振荡。

## 5. 失败时收集什么

- 两端设置页的"上次同步结果"（成功/失败、条目计数、错误信息）。
- 同步目录中的文件列表（`<deviceId>.<cursor>.pb`）。
- 桌面端 `%APPDATA%\MihonW` 下的日志 / Android logcat（`adb logcat | grep -i sync`）。
- 将现象记录到本文件下方"实测记录"一节。

## 6. 已知边界（不算缺陷）

- 取消已读 / 取消书签不会跨端传播（read/bookmark 保留 OR 语义，见计划文档 §7 与修复报告）。
- 物理删除不同步（tombstone 删除传播未启用，Phase 2.2）。
- 本地漫画（LocalSource，source=0）不参与同步。
- SAF 云盘目录（Nextcloud 等 DocumentsProvider）rename 失败时回退为非原子直写，极端情况下可能产生半写文件——若发现请记录。
